# Agent Brain v0.11.0 — Brain Telescope (web frontend)

## Overview

v0.11.0 ships the Brain Telescope: a locally-served web frontend that lets the **human** inspect the agent-brain's accumulated state without touching the CLI. The target audience is you — the developer watching your agents work — not the agents themselves. Agents continue to use `brain recall`, `brain write`, and the skill pack exactly as before; nothing in their interface changed.

The frontend is a read-mostly instrument panel: you see what your agents captured, how healthy the brain is, and what sources exist. You can trigger invalidation and navigate to recall from the source detail page. There is no write path for new captures in the browser.

Why a web frontend now: after v0.10.x the capture-recall loop was solid but opaque. The only way to inspect the brain was `psql` or CLI queries. Telescope closes that gap.

## Aesthetic direction — Crimson Matrix

The frontend uses the Crimson Matrix design system: Material Design 3 dark surface tokens, a crimson primary accent (`#da0037`), JetBrains Mono for headings and monospace elements, Geist for body text, 2 px border-radius throughout, no shadows (borders only). The result reads as a terminal-adjacent instrument panel — intentionally dense, high-contrast, no decorative chrome.

Canonical design manifest: `docs/design/crimson-matrix.md`. Screenshots: `docs/design/screenshots/`. Production source-of-truth for the Tailwind theme config: `src/brain/web/templates/base.html`. Full design spec: `docs/superpowers/specs/2026-05-28-brain-insights-frontend-design.md`.

## Pages shipped

- **`/` Dashboard** — hero metric (total captures), 30-day capture cadence sparkline + per-kind breakdown table, compliance block (under-captured sessions / thin sessions / strict mode toggle), staleness block (changed / missing / untracked counts), top-5 failure memories, embedding coverage ratio.
- **`/sources` Browser** — paginated list of all substantive captures (`kind` not in `{session_event, tool_call_output}`). Columns: ID, kind, project, truncated content, created timestamp. HTMX search-as-you-type on content (naive substring, 300 ms debounce). Kind-filter pills (Decision / Gotcha / Pattern / …) using HTMX `hx-get` that preserve the active search term via a hidden `q` field. Results update the `#sources-table` fragment without a full page reload.
- **`/sources/<id>` Detail** — full source content, all metadata fields (kind, project, tags, flagged, trust score, provenance_meta), action bar with three buttons: Invalidate (POST to `/api/sources/<id>/invalidate`), Revise (links to `brain revise` CLI instructions), Open in Recall (links to `/sources?q=<id>`).

## `brain serve` CLI

```bash
brain serve [OPTIONS]
```

| Flag | Default | Description |
|---|---|---|
| `--host TEXT` | `127.0.0.1` | Bind host. Use `0.0.0.0` for LAN access — **no authentication is provided**; only use on a trusted network. |
| `--port INTEGER` | `8765` | TCP port. |
| `--reload` | off | Enable uvicorn auto-reload on template and source changes. Uses import-string factory mode (`brain.web.app:create_app`) so uvicorn can re-import the app on change. Do not use `--reload` in production. |

Examples:

```bash
brain serve                       # localhost only, port 8765
brain serve --port 9000           # different port
brain serve --reload              # dev mode — templates hot-reload
brain serve --host 0.0.0.0       # LAN — NO AUTH
```

The server writes a startup line to stdout:

```
Brain Telescope running at http://127.0.0.1:8765
```

Ctrl-C to stop. The process is foreground; background it yourself with `&` or a process manager if needed.

## Tech stack

| Layer | Library | Version pinned |
|---|---|---|
| Application server | FastAPI | yes (`pyproject.toml`) |
| Templating | Jinja2 | yes |
| HTMX | HTMX 2 (CDN) | no (CDN, no SRI) |
| Alpine.js | Alpine.js 3 (CDN) | no |
| CSS framework | Tailwind Play CDN | no (can't pin Play CDN — vendor in v0.11.1) |
| Fonts | Google Fonts CDN (JetBrains Mono, Geist, Material Symbols Outlined) | no |
| ASGI server | uvicorn | yes |

No npm. No node. No bundler. No build step. Templates in `src/brain/web/templates/`, static assets (if any) in `src/brain/web/static/`. Adding a page is: create a Jinja2 template + add a FastAPI route. That's it.

SRI hashes are deferred to v0.11.1 — Tailwind's Play CDN dynamically generates CSS at request time and cannot be given a stable SRI hash. The fix is to vendor a prebuilt Tailwind CSS file.

## Known limits / gaps

- **No authentication.** `brain serve` binds to localhost by default; `--host 0.0.0.0` opens it to your LAN with no auth. Do not expose to the internet.
- **Dark theme only.** No light mode. The Crimson Matrix system is dark-only by design for v0.11.0.
- **No mobile layout.** The dashboard is designed for a desktop browser at ≥1280 px wide. Narrow viewports are unstyled.
- **Polling, not sockets.** The dashboard does not live-update. Refresh the page to see new captures. WebSocket push is deferred to v0.11.2.
- **HTMX search is naive substring.** The `/_htmx/sources` endpoint uses a `ILIKE %q%` query, not full-text search. On a large brain (>10k sources) this will be slow. FTS-backed HTMX search lands in v0.11.1.
- **Source-detail page composed from primitives.** No Stitch component variant exists for the detail layout — it was composed manually from the Crimson Matrix token set. A proper Stitch variant will be added in v0.11.1.
- **Invalidate action requires DB write.** The `POST /api/sources/<id>/invalidate` endpoint sets `t_valid_to = now()` directly; it does not go through the `brain.write.invalidate` helper yet. Behaviour is correct but does not emit a session event.
- **No pagination controls on sources browser.** The first page (50 results) is shown; page 2+ requires manual `?page=N` query param. HTMX-driven pagination lands in v0.11.1.

## Migration from v0.10.1

```bash
git pull
source .venv/bin/activate
uv pip install -e ".[dev]"   # picks up fastapi + uvicorn + jinja2 additions
brain serve                   # no DB migration needed — frontend is read-only
```

No alembic migration. The Telescope reads existing tables; it writes nothing to the schema.
