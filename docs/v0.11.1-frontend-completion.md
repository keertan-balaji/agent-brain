# Agent Brain v0.11.1 — Brain Telescope (frontend completion)

## Overview

v0.11.1 completes the Brain Telescope sidebar. v0.11.0 shipped three pages (Dashboard, Sources browser, Source detail). v0.11.1 adds three more — Recall console, Health observability, Knowledge graph — and a favicon that returns HTTP 204 instead of 404. All six sidebar links now resolve.

No schema migration. No new CLI flags. No changes to agent-facing skills.

## New pages

### `/recall` — Memory Retrieval Console

Full-text search over substantive sources (kinds not in `{session_event, tool_call_output}`). The query is passed to `brain.retrieve.search_sources` using Postgres `to_tsquery` over `content_tsv`. Results are ranked by `ts_rank_cd` descending and returned as a table with ID, kind, project, score, and a truncated content preview. Each row links to `/sources/<id>` for the full record.

Backend wiring: `src/brain/web/routes/sources.py` — `GET /recall` (full page) + `GET /_htmx/recall` (partial fragment, HTMX swap). HTMX triggers on keyup with 400 ms debounce (`hx-trigger="keyup changed delay:400ms"`). Alpine.js manages the loading-spinner state.

Data source: `brain_sources` table, `content_tsv` column (populated by the existing tsvector trigger).

Limits: FTS only — no vector lookup, no cross-encoder reranking. Hybrid recall (FTS + BGE-M3 + RRF + mxbai) is deferred to v0.12.0.

### `/health` — Observability

A single-page instrument view of brain health metrics. Rendered server-side on each request (no polling or WebSocket).

Sections:

| Section | Data source |
|---|---|
| Source counts by kind | `SELECT kind, COUNT(*) FROM brain_sources GROUP BY kind` |
| Capture counts (30 d) | `SELECT COUNT(*) FROM brain_sources WHERE created_at > now() - interval '30 days'` |
| Embedding coverage | `SELECT COUNT(*) FILTER (WHERE embedding IS NOT NULL) / COUNT(*)::float FROM brain_sources` |
| Staleness | `SELECT COUNT(*) FROM brain_sources WHERE t_valid_to < now()` |
| Retrieval latencies p50/p95 | `SELECT percentile_cont(0.5), percentile_cont(0.95) WITHIN GROUP (ORDER BY latency_ms) FROM brain_retrieval_log` (if table exists; falls back to N/A) |
| DB pool stats | `asyncpg pool.get_size()`, `pool.get_idle_size()` |

Backend wiring: `src/brain/web/routes/api.py` — `GET /health` renders `health.html`. The route is also used by the `GET /api/health` JSON endpoint (same handler, content-negotiated by `Accept` header).

### `/knowledge` — Source Graph

An interactive Cytoscape.js force-directed graph showing recent substantive sources and their relationships.

Graph structure:

- **Project cluster nodes** (ellipse, crimson border) — one per distinct `project` value in the last 200 sources.
- **Source nodes** (rectangle, surface-2 fill) — up to 50 recent substantive sources; colour-coded by `kind`.
- **Chunk child nodes** (small circle, muted) — direct children of sources where `parent_id IS NOT NULL`, limited to 50 total.
- **Edges** — `parent_of` (source → chunk); `in_project` (source → project cluster).

Cytoscape is initialised via an inline `<script>` block in `knowledge.html`. Graph data is serialised as JSON into a `data-graph` attribute on the container div and read by the init script. No XHR required; the full graph payload is embedded in the initial HTML response.

Backend wiring: `src/brain/web/routes/api.py` — `GET /knowledge` runs two queries (sources + parent relationships), builds the node/edge lists, serialises to JSON, passes to `knowledge.html`.

Data source: `brain_sources` — columns `id`, `kind`, `project`, `parent_id`, `created_at`.

Limits: edges are `parent_of` + `in_project` only. No entity-extraction edges, no embedding-similarity edges. Entity edges land in v0.12.0.

## `brain serve` CLI

Unchanged from v0.11.0. See `docs/v0.11.0-frontend.md` — the `brain serve` CLI section. Quick reference:

```bash
brain serve                       # localhost only, port 8765
brain serve --port 9000           # different port
brain serve --reload              # dev mode — templates hot-reload
brain serve --host 0.0.0.0       # LAN — NO AUTH, trusted network only
```

The new pages (`/recall`, `/health`, `/knowledge`) are registered automatically when the server starts. No additional flags or configuration required.

## Tech stack additions

| Addition | Library | Version | Notes |
|---|---|---|---|
| Graph rendering | Cytoscape.js | 3.30.4 (CDN) | Loaded in `knowledge.html` only; ~120 KB minified. No SRI — deferred to v0.12.0 alongside Tailwind vendoring. |

All other stack entries (FastAPI, Jinja2, HTMX 2, Alpine.js 3, Tailwind Play CDN, uvicorn) are unchanged from v0.11.0. Full stack table in `docs/v0.11.0-frontend.md`.

Cytoscape.js was chosen over D3 force-directed for v0.11.1 because it exposes a stable JSON element schema and handles node/edge creation without requiring a D3 selection mental model — simpler to wire to server-rendered JSON. D3 remains an option for v0.12.0 if richer axis control is needed for the retrieval analytics page.

## Favicon

`/favicon.ico` returns HTTP 204 No Content (no body). Registered as a static route in `src/brain/web/app.py`. Prevents 404 log spam on browser navigation. The route predates v0.11.1 (added during v0.11.0 polish) but was not documented.

## Known limits

- **Recall is FTS-only.** `/recall` uses `ts_rank_cd` over `content_tsv`. No vector lookup, no BGE-M3 embeddings, no cross-encoder reranking in this release. Hybrid recall (`brain recall` CLI parity) lands in v0.12.0. Callers who need semantic recall should continue using `brain recall` from the CLI or the PreToolUse hook.
- **Graph edges are structural only.** `/knowledge` shows `parent_of` and `in_project` edges. Entity-extraction edges (named-entity co-occurrence across sources) are deferred to v0.12.0. The graph is not interactive beyond pan/zoom/drag; click-to-open-source lands with the entity-edge release.
- **Graph is capped at 50 sources + 50 chunks.** The backend queries are `LIMIT 50` each. Large brains (>1 k sources) will show only the 50 most-recent substantive sources. A project-scoped filter (query param `?project=<name>`) is deferred to v0.12.0.
- **Source-detail still composed.** `/sources/<id>` is manually composed from Crimson Matrix tokens, not a Stitch component variant. No change from v0.11.0.
- **Cytoscape loads on every page.** The Cytoscape CDN script (~120 KB) is included in the base layout template, not just `knowledge.html`. It should be scoped to `knowledge.html` only; will be fixed and vendored with SRI in v0.12.0 alongside Tailwind.
- **No authentication.** Unchanged from v0.11.0 — see that doc for the threat model.
- **Dark theme only, no mobile layout.** Unchanged from v0.11.0.
- **No pagination on recall results.** First 50 hits are shown; no page controls. Pagination lands in v0.12.0 with the recall upgrade.

## Migration from v0.11.0

```bash
git pull
source .venv/bin/activate
uv pip install -e ".[dev]"   # no new Python deps; reinstall to pick up any pyproject.toml drift
brain serve                   # new routes register automatically; no DB migration needed
```

No alembic migration. The three new pages are read-only — they query existing tables. The `brain_retrieval_log` table is optional; `/health` falls back to N/A for latency percentiles if the table does not exist.

## Roadmap

### v0.12.0

- **Hybrid recall in `/recall`** — replace FTS-only with the full `brain recall` pipeline: FTS + BGE-M3 cosine + RRF fusion + mxbai cross-encoder reranking. Add pagination and a threshold slider.
- **Entity-extraction edges in `/knowledge`** — NER co-occurrence across sources; entity nodes as a third node class; click-to-open-source on node click.
- **Project-scoped graph filter** — `?project=<name>` query param to limit the graph to one project cluster.
- **Retrieval analytics page** — per-query latency histogram, hit-rate trends, miss analysis sourced from `brain_retrieval_log`.
- **Vendor Tailwind + SRI** — prebuilt Tailwind CSS replaces Play CDN; SRI hashes for all CDN assets (Cytoscape, HTMX, Alpine, Fonts). Cytoscape scoped to `knowledge.html` only.

### v0.13.0

- **Sessions timeline** — chronological view of session-event captures; diff-style entry display grouped by session UUID.
- **Hooks dashboard** — PreToolUse recall hit/miss log, hook latency distribution, skip-reason breakdown; sourced from `brain_hook_log` (new table, schema TBD).
- **Auth for LAN mode** — HTTP Basic or bearer-token header guard behind `--auth` flag; required before any `--host 0.0.0.0` usage outside a trusted private network.
